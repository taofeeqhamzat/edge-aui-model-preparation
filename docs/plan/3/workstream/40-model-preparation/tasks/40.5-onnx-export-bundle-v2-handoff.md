# Task 40.5 — ONNX Export, Bundle v2 and Framework Handoff

## Description

Export the semantic target head and integrate it with the browser runtime through a versioned
manifest, without overwriting the previous intervention-head artifact.

## Acceptance criteria

- [x] ONNX graph inputs are `sequence_input (batch, T, 18)` and `context_input (batch, 6)`; output
      is semantic outcome logits `(batch, 14)`.
- [x] INT8 quantization is applied; PyTorch/ONNX parity is verified within tolerance.
- [x] Model size and browser inference latency are measured; actual values are recorded.
- [x] `bundle.json` v2 records vocabulary/version, dataset version/hash, code commit, seed,
      environment, metrics, input/output contract and artifact hashes.
- [x] Framework can load the new artifact through configuration/manifest; vocabulary/order is read
      from the manifest, not hardcoded.
- [x] Previous `intervention_head*.onnx` and `bundle/v1.0.0` remain untouched and reproducible.
- [x] Framework model-version/provider reporting reflects the new artifact.
- [x] Tests cover graph contract, parity, quantization load, bundle schema/hashes and framework
      load.
- [x] `python3 -m pytest tests/test_intervention_head_export.py tests/test_reproducibility_bundle.py tests/test_semantic_head_export.py -q`
      passes.

## Notes

- Use a new artifact name (for example `task_outcome_head_v2.onnx`) rather than overwriting the old

- Do not claim the <500 KB payload target is met; record actual sizes.
- The manifest is the handoff contract; the framework must not infer vocabulary order from a
  hardcoded list.
